The saved call records of the two patterns whose prompts render the recalled-memory block no longer carry it into the persisted conversation blob (restores the review-F1 invariant that no memory text is persisted): `compactExecution` redacts the synthesize record it attaches to its `assistant_message` event and to the `error` event when the call failed as `LLMCallError`, and `router` redacts its call records on the conversational reply, the routing status, the missing-route error and the thrown-call error — under the `routing-and-replies` default the router prompt renders `data.memoryContext`, and `serializeContext` scrubs only the data keys, so an unredacted record's `rawInput` kept the block in the blob. The redaction is the same `redactCall` every decide-path record already goes through: `rawInput` / `rawOutput` / `parsedOutput` / `variables` drop and cost attribution survives; the live calls are unchanged. SPEC (memory recall, review-F1 section) and the GUIDE's `routerMemory` paragraph describe the channels; pins in `memory-recall.test.ts` run the synthesize leg and the router leg with a sentinel memory and were verified against the mutation that removes each site's redaction.
