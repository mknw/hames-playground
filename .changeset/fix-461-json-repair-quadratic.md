**`repairJson` / `repairJsonTracked`** now take time linear in their input (#461). Two regexes in the lenient chain were quadratic: the last-resort single-key handler, and the step that quotes bare values. Each had a lazy group followed by `\s*`, which re-scans a whitespace run each time the group grows by one character. The value step also re-scanned to the end of the input at every colon when no `,`, `}` or `]` followed. One malformed `tool_args` string of 200 000 characters cost ~14 s of synchronous CPU on the event loop, and model output can be steered by content the model has read. The same calls now take a few milliseconds. The handler now slices its value between the colon and the final `}`. The value step takes its value greedily and trims it afterwards, and it runs only up to the last terminator. Results are unchanged: a differential fuzz of 300 000 inputs against the previous implementation found no difference in any return value or thrown error.
