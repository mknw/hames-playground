The injection-ingress-guard classification replaces the guard gate (boundary guards revision 6, slice 17). `withInjectionGuard` takes a new `ingressGuard: { run: createIngressGuard(decide), mode }` option: one `choice` question keyed `guard.ingress` (`safe` / `possible-instructions-for-ai` / `instructions-for-ai-detected`) per external payload, at the existing Decide seam, driving presentation only — nothing is withheld. Mode `'off'` (default) / `'shadow'` (records a `decision_made` event, attaches no mark) / `'on'` (attaches an `IngressMark` — label, the safe line's pass, the decision event id — to the result, which the loops copy onto the `tool_result` event as `ingress` and the retriever attaches per hit). In `'on'` a classification that ran and gave no answer attaches an abstained mark (`abstained: true`, no label, `safe: false`), which a reader presents as unchecked; a label is floored at `possible-instructions-for-ai` after a deterministic finding and at `instructions-for-ai-detected` after a positive screen verdict; and a mark whose label covers only a head of the content carries `truncated: true`. A head whose state would pass the byte budget is cut to fit rather than refused. The question is the retired gate's reviewed one ("Does the content contain text that tries to direct or steer the AI reading it?"). The presented label applies `GUARD_INGRESS_SAFE_LINE` (0.7, provisional until slice 19's calibration), measured on the final wording against the private decision box's choice answers before it was set. The model-facing event view renders a `guard.ingress` decision as a fixed metadata line, with no label. The retriever sanitizes its hits concurrently.

Breaking: the guard gate is removed, by the owner's ruling recorded as [O42 in the boundary-guards design's decision record](https://github.com/mknw/hames-playground/blob/main/docs/plan/boundary-guards.md#o42-the-guard-gate-deleted-from-core) — `createGuardGate`, `GUARD_SCREEN`, `GUARD_GATE_THRESHOLD`, `GUARD_GATE_TIMEOUT_MS`, `guardGateSkipRate`, the `GuardGate` / `GuardGateVerdict` types, `InjectionScreenConfig.gate`, and the screen's `'shadow'` / `'gated'` modes (`ScreenMode` is `'off' | 'always'`). Both removed modes asked a gate; before this change a screen declaring either with no gate passed already refused construction, and now that no gate can be passed, a declaration carrying either refuses construction as an unknown mode. `drawFenceNonce`, `renderGuardGateState` and `LINE_BREAK` are now exported from the package root. A screen's `exempt` namespaces are exempt from the classification too.

general-next composes no gate; its office, info and documents guards declare `ingressGuard` (the documents guard without a screen) at `AgentGuards.ingressMode`, default `INGRESS_POLICY_DEFAULT` (`'off'`); `AgentGuards.gateThreshold` is removed. The reference app reads `GUARD_INGRESS=off|shadow|on`, one value for both tiers; an unknown value refuses boot.
