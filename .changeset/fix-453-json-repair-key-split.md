**`repairJson` / `repairJsonTracked`** no longer split one unquoted value into two keys at `, word:` (#453). The lenient chain's key-quoting step quoted every `, ident:` as a key. So `{query: sites like https://a.com, https://b.com}` came back as `{ query: "sites like https://a.com", https: "//b.com" }`, and `{query: MATCH (a) RETURN a, b:Person}` came back as `{ query: "MATCH (a) RETURN a", b: "Person" }`. Both results were well-formed, tagged `lenient-tokens`, and wrong. A key after a comma is now quoted only when its colon is followed by whitespace or by the start of a JSON value (`"`, `[`, `{`, a number, `true`/`false`/`null`). A colon glued to a bare word or a path is left alone. The rest of the chain then keeps the value whole, or declines it (#408) and the call throws. A glued `://` is never read as a member, so the URL list above now repairs to one `query`. **Behaviour change for callers**: inputs that used to return a split now throw. These include a Cypher label after a comma with no relationship pattern (`RETURN a, b:Person`, `SET a:Customer, b:Vendor`), which now behaves the same as the `-[r]-` form #408 already declined. They also include a compact object whose comma-led key's colon is glued to a bare word or a path (`{a:x,b:y}`, `{a: x, path:/work/in}`), and a `::` cast after a comma (`{query: SELECT id, created_at::date FROM orders}`). One input shape goes the other way: a genuine sibling whose protocol-relative or UNC value is written straight after its key's colon is now merged into the previous value, so `{q: x, src://cdn.example.com/a.js}` returns `{ q: "x, src://cdn.example.com/a.js" }` where it used to return two keys. The new rule does NOT close a `, word:` whose colon is followed by whitespace or by the start of a value: `{code: lambda a, b: a + b}` and `{query: site:example.com, intitle:"neo4j"}` both still split.
