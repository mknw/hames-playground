Add the out-of-run, non-blocking form of the human-in-the-loop request, and use it for memory confirmation. `proposeToHuman(ctx, request, { attended })` records a proposal in the context (replayed, never raised twice for one identity), `readProposals(ctx, now?)` lists the open ones from the whole log (a proposal outlives the turn that raised it), and `answerProposal(ctx, answers, { principal })` binds an answer to an open proposal with the option, flag and expiry checks a resume applies, all-or-nothing. `settleMemory` takes an optional `confirm` seam (`MemoryConfig.confirm`): an `ask` route then prepares the memories (vectors, read-only dedupe preview), proposes them as `memory.confirm` with counts and kinds only, and holds the payload under the request id, writing nothing; without the seam an `ask` still stores nothing. The report gains `proposed`, the skip reasons gain `already-proposed`. `applyMemoryProposal` writes what a person approved: only the flagged items, one transaction each, refusing an item whose target memory changed since the preview, a payload in another embedding space or a switched-off memory, and a no-op on retry. The organisational-graph target is unchanged: it never proposes and never writes.
