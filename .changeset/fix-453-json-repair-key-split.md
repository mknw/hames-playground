**`repairJson` / `repairJsonTracked`** no longer split one unquoted value into two keys at `, word:` (#453). The lenient chain's key-quoting step quoted every `, ident:` as a key. So `{query: sites like https://a.com, https://b.com}` came back as `{ query: "sites like https://a.com", https: "//b.com" }`, and `{query: MATCH (a) RETURN a, b:Person}` came back as `{ query: "MATCH (a) RETURN a", b: "Person" }`. Both results were well-formed, tagged `lenient-tokens`, and wrong. A key after a comma is now quoted only when its colon is followed by whitespace or by the start of a JSON value (`"`, `[`, `{`, a number, `true`/`false`/`null`). A colon glued to a bare word or a path is left alone. The rest of the chain then keeps the value whole, or declines it (#408) and the call throws. A glued `://` is never read as a member, so the URL list above now repairs to one `query`. **Behaviour change for callers**: inputs that used to return a split now throw. These include a Cypher label after a comma with no relationship pattern (`RETURN a, b:Person`, `SET a:Customer, b:Vendor`), which now behaves the same as the `-[r]-` form #408 already declined. They also include a compact object whose comma-led key's colon is glued to a bare word or a path (`{a:x,b:y}`, `{a: x, path:/work/in}`). Not closed: a colon followed by a space still reads as a key, because `{query: movies, limit: 5}` reads the same way as `{code: lambda a, b: a + b}`, and the second still splits.
