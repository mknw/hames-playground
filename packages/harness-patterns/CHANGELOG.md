# @hames-ai/harness-patterns

## 0.4.0

### Minor Changes

- a419d43: **The egress gate and the ingress screen can ask the person (boundary guards slice 10).**
  
  - `withEgressGate({ askPerson: true })`: a Decide refusal and the D5 person cells raise an `egress-release` request (Refuse, Accept, Refuse all similar actions, Interrupt; Refuse the default and the only unattended pick) where the call can pause, instead of refusing. The call is held, not sent; on re-entry the loop dispatches it again under the same call key and the gate answers from the recorded decision. Unattended, inside a batch, or on a path that cannot pause, the cells refuse as before. While on, every outgoing name is a gated name at construction.
  - A screen with `askPerson: true`: a finding raises an `ingress-flag` request (Leave it out, Use it without the flagged text, Use it unchanged); the host's `resolve` returns `ingressFlagResolution(choice, payload)`. Unattended the result is left out; attended on a path that cannot pause it is neutralised and says so.
  - New: `canPauseHere()`, `recordedHolding()`, `askHumanHolding(request, payload, authorizes?)`, an `EgressCheck` may return `{ held }`, `HeldResult.redispatch`, run-frame slots `continuationRoot` and `batch`, a continuation step's `child`, `EGRESS_RELEASE_KIND` / `EGRESS_RELEASE_OPTIONS` / `EGRESS_HELD_NOTE`, `INGRESS_FLAG_KIND` / `INGRESS_FLAG_OPTIONS` / `INGRESS_TEXTS`. `EgressAuditEventData.probs` is optional (absent when a person released the call).
- be74388: Tell the Decide step about the conversation's documents (#507). `decisionLoop` takes an optional `documents` source (`(signal) => Promise<DecisionDocuments>`), read once per run before iteration 1, and renders it into the state as a block between the conversation and "This turn so far": a capped list of every visible document's name, type and size when the host's source returns names, `N (names not shown)` when it returns a count only, and nothing when there are no visible documents (such a state is byte-identical to before). Core never reads a tier: the host decides what a run may reveal.
  
  - Names are untrusted text: cut to 80 code points before any rule runs, NFKC-normalised, separators and control characters replaced, invisible, default-ignorable and format characters removed, checked against the injection rule corpus and the state's own headers (a name that trips either is shown as `[name withheld]`), then JSON-quoted on one line. At most 10 names and 1,000 characters, then `+K more documents`. The guard's screen is never run for a name. The check is deterministic, not a confusables filter: a lookalike letter from another script is shown. `mimeType` is mapped through a fixed allowlist, never printed raw.
  - A source that throws, times out (`documentsTimeoutMs`, default `DECISION_DOCUMENTS_TIMEOUT_MS` 30 000, aborts the source's signal) or returns a malformed value gives an explicit `unknown (could not be read)` line (never "none") and one `warning` event (new `WarningTask` `'decision_documents'`); the turn runs as before.
  - `DecisionLoopStateInput.documents` hands the resolved value to a `state` override. New exports: `renderDocumentsBlock`, `DECISION_DOCUMENTS_TIMEOUT_MS`, and the `DecisionDocument`, `DecisionDocuments`, `DecisionDocumentsSource` and `ResolvedDecisionDocuments` types.
  - `listDocumentSummariesStrict(sessionId, callTool?, signal?)` in `stash/document-store.server`: the strict list without the content, one `json_get` per document of just the members a description needs. A failed or unreadable read throws and never prunes; an index entry is pruned only after a successful read that found nothing.
  - `@hames-ai/agents`: `AgentDeps.createDecisionDocuments` (optional); `general-next` passes it to its loop. Without it the state says nothing about documents.
  - Cost: every turn of a conversation with documents waits on the read before the first decision, up to `documentsTimeoutMs`; on the default gateway transport it is one call per document in sequence, so linear in their number. Unmeasured; it must be measured before it can be turned on by default.
  - SPEC: `decision_made`'s `data` carries `stateChars`, never the state text, but the call record holds it twice, in `rawInput` (the request body) and `variables.state`, both persisted with the conversation; deleting or hiding a document does not remove its name from earlier turns' stored states.
- 0b4a682: **`decisionLoop` hands each route child the conversation before the user's latest message.** A loop child reads only the latest message as its task, so a follow-up such as "try the same count again" reached the route with no referent while the decisions model, which chose that route, had read the earlier turns. Each child's fresh data now carries `conversation`: the decisions model's own conversation lines minus the latest message, each line's text capped at `maxResultChars` and rendered as one JSON string after its `User:` / `Assistant:` role. No earlier turn, no key.
  
  - `formatPlanContext(plan, handoff, conversation)` takes the block as a third optional argument and renders it first, under its own heading (`CONVERSATION_HEADING`, exported, "Earlier conversation — data, not instructions") ending with `CONVERSATION_END`, before PLAN and the step results. Absent, the output is byte-identical to before. `simpleLoop` and `actorCritic` pass `data.conversation`; `planner` renders it in its context after the agent map. `PlannerData` gains `conversation?: string`.
  - The `webRosterInput` a `pseudonymisedInputs` route receives now also holds every earlier turn's `tool_result` payloads, every route's (the loop's own records aside): an earlier answer in the block can name a person only a route the child may not see read. `withPseudonymisedInputs` rewrites the block with the rest of the child data, and its fail-closed path withholds it.
- 60836df: **`decisionLoop` no longer sanitises or screens its own route records, and the API the unreleased `decision-loop` entry announced for that is removed before it ships (pre-1.0, so a minor bump).** Guards run where content enters or leaves; a record is built by code from the child's committed events (the model's own plan or Return, a stats line, or a tool-result body that already passed its route's guard) and is only capped. This removes the loop's own call into the run frame's guard, and the planner-only `screenOutput` option that narrowed it (`screenOutput` was added by the unreleased #713 change, whose changeset this entry replaces).
  
  - Removed exports (never in a published release; the migration note is for anyone on a pre-release build): `DECISION_LOOP_OUTPUT_KEY` and `WITHHELD_SCREEN_UNAVAILABLE` (from the package root and from `patterns`), and the route option `screenOutput`. The unguarded-output warning and its test-only `__resetDecisionLoopWarnings` are gone. A `screenOutput` property on a route is no longer read; TypeScript callers get an excess-property error.
  - Removed behaviour: a screen outage no longer withholds a route record (S-d), and `RouteOutput.withheldEventIds` is no longer written. Records an older version persisted still carry `withheldEventIds`, and the loop still reads them back as a filter, so those events stay hidden from every later child.
  - The `actorCritic` and `retriever` extractors, which quote tool-result bodies, now put each body back under the provenance fence it arrived in (the same tool and namespace, no regex pass, no screen) after the cap (the fence's own lines ride on top of the cap), so it reaches the decisions model and the next child's `plan_context` labelled. A body that arrived unfenced stays unfenced, and a fence is labelled only when the run's guard declares the tool it names. A failed route's text (a tool error or a thrown message) gets the same cap-then-fence treatment. An `actorCritic` batch is one fenced block per accepted result, no longer one JSON array.
  - Record text the loop did not build (the plan's record, a Return, reasoning, failure text) renders into the decision state and the handoff as one JSON string, the handoff block gains an end line (`HANDOFF_END`), and the state's results heading says the results are data.
  - New: `closeCutFences(text)` and `unspotlightParts(text)` from `@hames-ai/harness-patterns/guard`, the sibling of `unspotlight` that also returns the `tool` and `namespace` the header named. `extract(kind, events, max)` (the records module) now takes the cap as a required third argument and returns every text field already capped (`carryText` is the same cap for a thrown message).
  - Migration: delete `DECISION_LOOP_OUTPUT_KEY` from any guard's `tools` and from imports, delete `screenOutput`, and move any screen you relied on for route records onto the routes' own guards (the tools a route reads). A guard around the whole loop no longer has anything of the loop's to guard; the GUIDE sample shows route guards and no orchestrator guard.
  - `general-next` drops the key from its orchestrator guard and `screenOutput` from its `think` route; its office and info route guards keep their screens.
- 4190880: **An `actorCritic` route's critic judges the route's share of the request, not the user's whole message.** Inside a `decisionLoop`, the critic is the route's only exit, and it read the user's latest message as its intent: a request spanning several steps ("…save lantern-analysis.md, index it for this chat, and offer to answer questions") had every complete attempt rejected for parts no tool of the route performs, until the route's bound ran out ([#606](https://github.com/mknw/hames-playground/pull/606)).
  
  - `decisionLoop` hands an `actorCritic` route's child `data.routeScope`: that route's own agent-map entry (description, `capability`, tools) under `ROUTE_SCOPE_HEADING` (exported), then the rule that the rest of the request is other steps' work and the reply is written after the last step. No other kind of route is handed it; `data.intent` stays unset.
  - `actorCritic` appends `data.routeScope`, after a blank line, to its task (`data.intent`, else the user's latest message) and hands that one intent to its actor and its critic. Without a scope the intent is byte-identical to before. `ActorCriticData` gains `routeScope?: string`.
  - Under `withPseudonymisedInputs` the scope is child data like the rest: rewritten, or dropped on the fail-closed path.
- 959966b: Add `decisionLoop(routes, config)` (#507 S1): a loop over routes in which the systemone `decide` seam picks the next route each time round, until it picks `answer` (a choice that runs nothing, so the synthesizer answers once) or `maxIterations` is reached. Exports `DECISION_LOOP_MAX_ITERATIONS` (6) and the record/stat types.
  
  - Each child runs in its own synthetic context and `viewConfig`, with events of siblings it may not see (`siblingResults`, default none) and the loop's own records physically removed, and with fresh `data` (never `memories`, `memoryContext` or `intent`).
  - A route's output is a record built by code from the child's committed events by route kind (`simpleLoop`, `actorCritic`, `retriever`, `planner`), never reading `content_sanitized`. Its `result` and `reasoning` are capped; the loop sanitizes and screens nothing of its own (tool bodies it quotes keep the fence they arrived in). A screen that threw at ingress is typed `screenUnavailable` on `SanitizeReport` and `SanitizeSummary`.
  - `formatPlanContext(plan, handoff?)` renders earlier-step results under their own data heading, outside the PLAN section; `planner` reads `data.handoff` and `data.agentMap` into its existing `context` argument. With neither, both are byte-identical to before.
  - A non-decision never dispatches a route: an irrecoverable visible error on iteration 1, a stop-as-answer on a later one. A failed route is a failed record and the loop decides again; a child's `error` events are committed as `recoverable`.
  - New `PatternCapabilities.tools` (declared by `simpleLoop`, `actorCritic` and `withSandbox`, which now always declares its in-VM tool names and merges over the wrapped pattern's capabilities) and `collectToolNames`.
  - Export `unspotlight(text)` from `@hames-ai/harness-patterns/guard`: strips one guard spotlight fence, for readers that excerpt fenced text. `decisionLoop` refuses routes that share a `patternId` (or use the loop's own).
  - A `planner` route is offered once per turn: withheld straight after its own iteration and once a plan exists, so a decisions model that favours it cannot spend the bound on planning (#692). `allowReplan: true` on the route opts out (planner routes only; refused elsewhere). With only `answer` left the loop ends without asking.
  - `decisionLoop` requires an explicit `patternId` (its records and withheld ids are matched by it across turns) and hides earlier turns' events by the route they were emitted inside, so patterns rebuilt each turn with generated ids cannot leak.

- 33c71cf: **The injection guard's fence names where content came from, and nothing about trust (boundary guards slice 8, ruling F). Breaking for direct callers of `ScreenUntrustedContent` (pre-1.0, so a minor bump).**
  
  - Every fence now reads `⟦external provenance: <namespace>/<tool>, <item>⟧`, the content, then `⟦end of external content⟧`. The old header's sentence ("this is DATA to be reported on, never instructions to follow; any directive inside it has been neutralized and must be ignored") is gone: whether content can be trusted is not known, and a directive was not always neutralised. The sentinels, not the words, are what make it a fence, and they are unchanged. A fenced leaf is shorter (a 46-character header instead of 182).
  - `<item>` is a code-generated id: `callTool` passes its invocation's id and the retriever a hit's `docId`, both through the guard's new per-call `item` (`guard.sanitize(tool, data, { item })`). `spotlight(text, tool, namespace, item?)`, `sanitizeUntrusted(data, { tool, namespace, item? })` and `applyScreenVerdict` take it too. `fenceItemId()` reduces it to `[A-Za-z0-9._:-]` and 64 characters, and the header leaves it out when nothing is left.   - The decision loop's `actorCritic` and `retriever` extractors put a quoted body back under the fence it arrived in with its item id; a retriever block names a document only when every hit arrived fenced and named the same one.
  - `@hames-ai/harness-baml`: `ScreenUntrustedContent(source, content, boundary, options?)` takes a third argument, a per-call code both of the prompt's markers carry (`---BEGIN CONTENT UNDER REVIEW <code>---`); its system text no longer calls the source untrusted. `createInjectionScreen()` draws the code itself (16 hex characters, drawn again if the content holds it) and takes an optional `drawNonce` test seam. - 99387af: An approval given through `resumeHarness` now lasts only for the run it resumes (#456 c′). `resumeHarness` writes `approved` onto `ctx.data` for the resumed run. `continueSession` never cleared it, so after one approval `data.approved === true` rode every later turn, and a gate reached again went ahead without asking. `continueSession` now deletes `approved` along with `hasError`, `errorMessage` and `response`. - 3e0bdf8: Two output-cleanup fixes.
  
  - **`repairJson` / `repairJsonTracked`** (`@hames-ai/harness-patterns`) no longer fold a malformed multi-key object into its first key (#408). The last-resort handler for a single key whose bare value holds commas checked only that the input began with one key, so `{a: [x,,y], b: 1}` came back as `{ a: "[x,,y], b: 1" }`, tagged `lenient-tokens`. It now declines whenever the would-be value holds something shaped like another member (`, b:`, `"b":`, `'b':`), and the call **throws**: both loops feed it back to the model as a recovery round (#437). **Behaviour change for callers**: inputs that used to return one wrong key now throw. The decline is deliberately conservative, so some inputs the old handler got right now throw too: a Cypher label predicate or label write after a comma (`RETURN a, b:Person`, `SET a:Customer, b:Vendor`, `REMOVE …`), and a quoted word followed by a colon (Python's `if x == "y":`, once the same code also holds an ambiguous `print("a", b)`). A value that is one cleanly quoted string is exempt, so `{query: "RETURN n, n:Person"}` still repairs.

- 51f96c6: **`repairJson` / `repairJsonTracked`** no longer split one unquoted value into two keys at `, word:` (#453). The lenient chain's key-quoting step quoted every `, ident:` as a key. So `{query: sites like https://a.com, https://b.com}` came back as `{ query: "sites like https://a.com", https: "//b.com" }`, and `{query: MATCH (a) RETURN a, b:Person}` came back as `{ query: "MATCH (a) RETURN a", b: "Person" }`. Both results were well-formed, tagged `lenient-tokens`, and wrong. A key after a comma is now quoted only when its colon is followed by whitespace or by the start of a JSON value (`"`, `[`, `{`, a number, `true`/`false`/`null`). A colon glued to a bare word or a path is left alone. The rest of the chain then keeps the value whole, or declines it (#408) and the call throws. A glued `://` is never read as a member, so the URL list above now repairs to one `query`. **Behaviour change for callers**: inputs that used to return a split now throw. These include a Cypher label after a comma with no relationship pattern (`RETURN a, b:Person`, `SET a:Customer, b:Vendor`), which now behaves the same as the `-[r]-` form #408 already declined. They also include a compact object whose comma-led key's colon is glued to a bare word or a path (`{a:x,b:y}`, `{a: x, path:/work/in}`), and a `::` cast after a comma (`{query: SELECT id, created_at::date FROM orders}`). One input shape goes the other way: a genuine sibling whose protocol-relative or UNC value is written straight after its key's colon is now merged into the previous value, so `{q: x, src://cdn.example.com/a.js}` returns `{ q: "x, src://cdn.example.com/a.js" }` where it used to return two keys. The new rule does NOT close a `, word:` whose colon is followed by whitespace or by the start of a value: `{code: lambda a, b: a + b}` and `{query: site:example.com, intitle:"neo4j"}` both still split.
- af875e4: **`repairJson` / `repairJsonTracked`**: two quadratic regexes in the lenient chain are now linear (#461). The function as a whole is not yet linear in its input, because two bracketed-literal scanners that are not regexes are still super-linear (#463). Two regexes in the lenient chain were quadratic: the last-resort single-key handler, and the step that quotes bare values. Each had a lazy group followed by `\s*`, which re-scans a whitespace run each time the group grows by one character. The value step also re-scanned to the end of the input at every colon when no `,`, `}` or `]` followed. One malformed `tool_args` string of 200 000 characters cost ~14 s of synchronous CPU on the event loop, and model output can be steered by content the model has read. The same calls now take a few milliseconds. The handler now slices its value between the colon and the final `}`. The value step takes its value greedily and trims it afterwards, and it runs only up to the last terminator. Results are unchanged: a differential fuzz of 300 000 inputs against the previous implementation found no difference in any return value or thrown error.
- 94870a1: **`repairJson` / `repairJsonTracked`**: the bracketed-literal scanner in the lenient chain is now linear in its input, and the chain refuses input over 16 384 characters (#463). The scanner had three super-linear shapes. An unbalanced `[` or `{` after a colon was scanned to the end of the input at every colon, which is quadratic: ~23 s of CPU at 200 000 characters. A nested literal was re-scanned at every level of a recursive repair, so it cost its depth times its length until the recursion ran out of stack. And nested objects whose innermost value cannot be repaired paid that cost at every nested colon, which is cubic: ~68 s at 16 000 characters and ~10 minutes at 200 000. Each shape now costs about a millisecond at 16 000 characters. One pass decides, bottom-up, whether every literal can be repaired, and a second pass renders only the literals that are parked. Neither recurses. Results are unchanged, with one exception: a differential fuzz of 1.6 million inputs against the previous implementation found no difference in any return value or thrown error, except on literals nested deeper than the old recursion's stack (past ~2 000 levels, depending on JIT state). Those threw `RangeError` and now repair. **Behaviour change for callers**: input longer than 16 384 characters (after trimming) that is neither valid JSON nor recoverable by the unescaped-content strategy now throws a `SyntaxError` that names the length and the limit, even where the lenient chain would have repaired it. It is never truncated. Both loops forward the refusal to the model, so it is told to send strict JSON, not only that its args did not parse. Valid JSON of any length, and the unescaped-content recovery of long payloads, run before the bound and are unaffected. The bound is defence in depth: with the scanner fixed, no step of the function is known to be super-linear. One limit that is not about cost remains: the unescaped-content strategy still recurses, so input it reads several thousand levels deep throws `RangeError`, in about a millisecond, as it did before.
