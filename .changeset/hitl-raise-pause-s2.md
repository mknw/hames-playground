Raise and pause (#433, slice S2). **Not released alone**: this slice can pause a run, and the answer-bound `resumeHarness` that continues one arrives in S3, so no package release happens between S2 and S4 (#433 slice plan, F19b).

- **`askHuman(request)`** asks a person to decide, from inside a run: a pattern body, or a tool executor that holds no scope. It replays a decision the run already holds for the same kind, key and option set (if the choice is still an available option of the new request), applies the request's unattended rule when nobody is there, or raises a `hitl_request` and returns `pending`. Request ids are `crypto.randomUUID()`. A raised request records `resumeAt` (the top-level index and every top-level pattern name) and the run's opaque inference tier. New types: `HitlRequest`, `HitlOutcome` and `HeldResult`.
- **Validation at raise.** An invalid request throws `HitlRequestError`: fewer than two options, duplicate option ids, a default that is missing or unavailable, an unknown `unattended` rule, `'stop'` with no `stopsRun` option, duplicate flag ids on an option, a `required` flag on an option the unattended rule may pick, and a `kind` containing `:`. `askHuman` also throws outside a run frame, in a frame with no `hitl` slot, and in one no `runChain` owns.
- **`resolveUnattended(request)`** is the unattended rule. It never picks an option without `unattended: true`. `apply-default` takes the default when the rule may pick it, then the first available option it may pick, and otherwise stops the run with no choice. `stop` takes the first stopsRun option the rule may pick, and `park` decides nothing.
- **`held(outcome, note?)`** builds the placeholder a gated executor returns instead of the content. **`hitlPending()`** is the stop check between steps.
- **The run frame gains a sixth slot, `hitl: { attended }`.** `amendRunFrame` passes it by reference, so it survives `withInjectionGuard` and `withSandbox`. It refuses a second one below an open one. **Behaviour change**: `harness()`, `continueSession()` and `resumeHarness()` supply `{ attended: true }` when they open the frame. They supply nothing when they join a host's frame.
- **The pause.** The `runChain` that owns the slot commits the slot's HITL events straight into the context after every pattern, including one that threw. A request still waiting then ends the run `paused`. The paused pattern's events are committed, but its data is not, so re-entry starts from the same data. `error` wins over a pending request. An unattended choice that stops the run ends it `done`, with a fixed response. A `runChain` nested inside one of the owner's patterns neither commits nor pauses.
- **The stop checks.** `simpleLoop` stops after a single call and after a batch. `actorCritic` stops after a single call and after a batch, before the critic is asked. A sequential `runBatch` skips the calls after one that waits. The `chain()` combinator runs no further child. None of these records an error.
- **Behaviour change**: `commitEvents` and `chain()` now drop EVERY `hitl_*` event a scope carries, with a `console.warn`. No legitimate HITL event travels through a scope any more, so the minted-event set S1 used is gone. This also removes the case where two installed copies of the package dropped each other's events. `hitl_request` and `hitl_response` are no longer in the always-committed set, because no commit strategy ever sees them.
- `emitLive(event, force?)`: `force` emits whatever the pattern's `liveEvents` says. `askHuman` uses it, so the question reaches the listener while the run is still going.
